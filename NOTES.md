# Заметки о реализации MVP

Документ фиксирует толкования `Архитектура.md` там, где он неоднозначен, умалчивает или
противоречив, а также осознанные отступления и найденные проблемы спецификации.
Сам `Архитектура.md` не изменялся. При выборе толкования приоритет у принципа
безопасного отказа (1.1.3), изоляции данных и машины состояний (2.3.4).

## 1. Толкования

### Инфраструктура и структура проекта

- **Размещение кода без отдельных модулей (3.4.2).** Структура проекта не предусматривает
  модулей для логирования и общих веб-помощников, а лишних файлов добавлять нельзя.
  Поэтому настройка логирования и фильтр маскирования access-лога находятся в
  `app/config.py` (стартовая конфигурация процесса, используется и web, и worker), а общие
  элементы веб-слоя (шаблоны, коды ошибок 3.1.3, обработчики ошибок, зависимости
  аутентификации, форматирование) — в `app/routes/__init__.py`.
- **Миграции.** Эталонная схема 2.3.1 создаётся цепочкой Alembic-ревизий: `0001` —
  `system_state` (нужна на этапе 1 для heartbeat и `/healthz`), `0002` — остальные таблицы.
  DDL в миграциях повторяет эталонный SQL дословно.
- **Сборка образа (3.4.3).** Индекс PyTorch задан аргументом сборки `TORCH_INDEX_URL` со
  значением по умолчанию из спецификации (`https://download.pytorch.org/whl/cpu`), языки
  весов EasyOCR — аргументом `OCR_LANGS=ru,en` (веса скачиваются «для `OCR_LANGS`»).
  Порядок слоёв: шрифт → PyTorch → стек OCR и веса → зависимости приложения → код;
  списки зависимостей извлекаются из `pyproject.toml` в отдельной стадии сборки, поэтому
  изменение кода (и даже зависимостей приложения) не пересобирает тяжёлые слои.
  `.dockerignore` не предусмотрен структурой, поэтому `COPY` перечисляет только нужные
  каталоги — `.env` и `.git` в образ не попадают. Процессы работают от непривилегированного
  пользователя `app`.
- **Версии зависимостей.** Все прямые зависимости закреплены точными версиями в
  `pyproject.toml`; `torch==2.14.0` и `torchvision==0.29.0` закреплены в `Dockerfile`
  (ставятся из CPU-индекса). Дополнительно закреплены значимые транзитивные зависимости:
  `starlette`, `limits`, `numpy`, `opencv-python-headless`. Для OpenCV выбрана ветка 4.x
  (4.14.0.94), а не вышедшая 5.0: EasyOCR 1.7.2 разрабатывался под 4.x. Образы также
  закреплены: `python:3.12.14-slim`, `postgres:16.15`, `axllent/mailpit:v1.31.2`,
  `caddy:2.11.4`.
- **Пароль PostgreSQL.** В 3.4.1 нет переменной для пароля контейнера `db`, а в
  эксплуатации пароль должен быть стойким. Добавлена переменная `POSTGRES_PASSWORD`
  (в `.env.example` с пояснением); она должна совпадать с паролем в `DATABASE_URL` и
  `TEST_DATABASE_URL`.
- **Порты в разработке** (`8000`, `8025`, `1025`) публикуются только на `127.0.0.1`.
- **Служебные страницы FastAPI** (`/docs`, `/redoc`, `/openapi.json`) отключены: это были бы
  эндпоинты сверх перечня 3.1.2.

### Конфигурация и логирование

- **Проверки при старте (3.4.1)** реализованы валидаторами `Settings`; при ошибке web
  (импорт `app.main`) и worker (`python -m app.worker`) печатают «Ошибка конфигурации» с
  перечнем причин без значений переменных и завершаются с кодом 1. Дополнительно
  отклоняются заведомо бессмысленные значения (неположительные лимиты и сроки, порог
  вне 0–100, неизвестный `DISPLAY_TZ`).
- **Логи (3.2.10).** Формат: время, уровень, имя логгера, `request_id` (если известен),
  сообщение. Логгеры uvicorn направлены в общий обработчик stdout; фильтр маскирования
  токенов стоит и на логгере `uvicorn.access` (изменяет запись до любых обработчиков), и на
  обработчике stdout. Логгеры `sqlalchemy`, `PIL`, `multipart` и др. понижены до WARNING:
  иначе при уровне DEBUG SQLAlchemy выводит строки результатов, где есть ФИО и email.
  Движок БД создаётся с `hide_parameters=True`, чтобы значения параметров не попадали в
  тексты исключений.

### Тесты

- **Детерминированный профиль test.** `tests/conftest.py` удаляет из окружения все
  переменные приложения и задаёт профиль test (3.4.1): база `app_test`, `memory`, `fake`,
  тестовые `SECRET_KEY`/`MASTER_KEY`. Остальные параметры берут значения по умолчанию из
  3.4.1, поэтому настройки `.env` (например, укороченный период ожидания для ручной
  проверки 4.6) не влияют на тесты.
- **Часы в тестах** замораживаются в начале каждого теста на текущем времени.

## 2. Отступления

- Добавлена библиотека **httpx** (вне 2.1): без неё не работает `fastapi.testclient.TestClient`,
  прямо названный в 4.4. Используется только в тестах.
